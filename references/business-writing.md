# 提案書・PowerPoint・業務文章の編集

この資料は、be-humanを業務文章に適用するときに読む。基本方針は「読み手が次の判断をできるだけの情報を、誤解なく渡す」。人間らしさを理由に、なれなれしくしたり、主観や比喩を足したりしない。

参照する節：1 読み手と判断／2 主張の強さ／3 提案の組み立て／4 スライド／5 箇条書き・表／6 文体・用語／7 文書別の注意／8 推敲。

## 1. 読み手が知りたいことから選ぶ

依頼や既存資料から、読み手、用途、求める判断、前提知識、媒体を押さえる。全てを質問してから始める必要はない。判断に影響する不足だけ確認する。

| 読み手・場面 | 前に出す情報の候補 |
| --- | --- |
| 決裁者への提案 | 何を決めたいか、費用と効果、成立条件、主要な懸念 |
| 現場担当者への運用説明 | 誰が何をするか、対象、タイミング、例外時の扱い |
| 技術担当者との検討 | 前提条件、仕様、確認結果、未検証事項 |
| 顧客への提案 | 顧客の課題、提案する対応、双方の役割、判断材料 |

必要な情報を確かめる際は、担当者、相手、作業、目的、対象、日時、場所、方法、数量・金額・期間を候補にする。文ごとに全項目を詰め込まない。元資料にない担当や日程を埋めず、重要なら確認事項にする。

## 2. 語尾で主張を強めない

主張の種類を先に判別する。自然な語尾への変更でも、次の境界は越えない。全てにラベルを付ける必要はなく、文で区別できればよい。

| 種類 | 書き方の例 | 保つ情報 |
| --- | --- | --- |
| 観察・実績 | 試験した20件中18件で回答案を作成できた | 対象、測定方法、期間、分母 |
| 他者の説明 | A社は、同社試験で時間が短縮したと説明している | 発言者、出典、実証の主体 |
| 解釈・仮説 | 入力項目の多さが離脱の一因と考えられる | 解釈であること、根拠、他の可能性 |
| 試算・予測 | 月800件の場合、作業時間を約40時間減らせる試算 | 計算条件、対象作業、費用の範囲 |
| 目標 | 回答案の作成時間を20％短縮することを目指す | 指標、対象、目標であること |
| 提案 | まず一部署で試行することを提案する | 実施前であること、提案する範囲 |
| 合意・実施予定 | 合意に基づき、来月から試行する | 合意の有無、担当、時期 |

ここにある数値・設定は説明用の架空例。実案件に流用しない。

推敲時には特に以下を点検する。

- 「できる」の根拠は、機能の有無、条件付きの実現可能性、実測結果のどれか。可能だから全件で成功するとは限らない。
- 「につながる」は、意図する効果か、検証済みの結果か。目的なら「〜を目指す」、未検証なら検証事項として扱う。
- 「最大」「平均」「約」「見込み」、比較対象、除外条件を消していないか。最大値を平均的な効果のように見せない。
- 率の差と相対変化を混同していないか。例えば40％から50％への変化は10ポイント増であり、元の値に対しては25％増。必要な比較だけ、基準を示して書く。
- 相関や前後比較だけで原因を断定していないか。
- 根拠のない「業界初」「最適」「圧倒的」「確実」を、別の強い形容詞で残していないか。

未確認の断定を見つけたら、単に「可能性がある」に弱めて残すのでも、黙って削るのでもなく、根拠を確認する。確認できなければ、草案では要確認と分かるよう扱うか、資料にある目的・提案の範囲で書ける部分を示す。文体だけを整えて内容まで検証済みと見せない。

## 3. 提案は、判断に必要な筋道でつなぐ

材料がそろっている場合は、提案の要点、現在の状況と根拠、提案する対応、期待する効果と成立条件、実施方法、判断してほしい事項をつなぐ。必ずこの順・この見出し・この枚数にする規則ではない。指定書式を優先し、不足資料を埋めるための創作をしない。

特に確認するのは、隣り合う主張のつながり。

- 現状のどの事実が、対応の必要性を支えているか。
- 提案する作業が、なぜその問題に効くと考えるのか。
- 効果を受ける相手と、作業を負担する相手は誰か。
- 費用・体制・顧客側の作業・対象範囲が分かるか。
- 代替案や見送る場合との比較が、今回の判断に必要か。
- 本導入が未決定なら、試行の結果をどう評価して次を決めるか。基準が未定なら未定と扱う。

「課題」「解決策」「効果」の箱だけ埋めても、関係が書かれていなければ提案は伝わらない。反対に、軽い相談の文に費用対効果表や導入計画一式を勝手に増やさない。

社外への提案は、提案者の能力を褒める文より、顧客に起きる変化を資料の範囲内で示す。顧客の失敗や能力を断定する言い方を避け、観察できる状態と業務上の影響を書く。配慮のために不都合な事実を隠す必要はない。

## 4. PowerPointでは文章の役割を分ける

### タイトルと見出し

ファイル・表紙の題名は、対象と資料の用途が分かるものにする。説明スライドの見出しは、そのページの主張・問い・作業が読めるようにする。

「導入効果」だけで内容がつかめない場合は、根拠がある範囲で「回答案の作成時間を比較する」「試行では定型問い合わせの作成時間が短縮」のように焦点を示す。結果が未検証なら成果を言い切らず、「試行で確認する効果」とする選択肢もある。

全ページを断定文にする必要はない。目次、章扉、比較表、工程図、参考資料には「実施体制」「料金比較」などの項目名が役立つ。「検討」「案」「予定」を見出しから消して、決定事項のようにしない。

### 本文、図表、補足

- 一つのスライドで読み手に何を理解・判断してもらうかを定める。必要な比較項目まで一つに減らす意味ではない。
- 見出しの主張に必要な根拠を近くに置く。本文は見出しの言い直しだけにしない。
- 投影して話す資料は要点を短くし、詳しい説明を発表者ノートへ移せる。送付して単独で読まれる資料には、判断に必要な説明を残す。ノートが納品先で読めるとは仮定しない。
- 重要な制約は主張と一緒に読めるよう残す。例えば「作成時間20％削減」という見出しに対して、小さな脚注だけで「目標」とするのは避ける。
- 数字には、必要な単位、対象、期間、実測・試算の別を付ける。図表では軸・凡例・注記も文章の一部として照合する。出典表示と主張の対応を保つ。
- 短い名詞句、体言止め、ラベルと値の組み合わせを使ってよい。「対象：営業部」は自然な表現。文字数だけを減らすために必要な助詞を全て削らない。
- 文字が収まらない場合は、重複を削る、表現を組み替える、補足を分ける。条件や否定語を落とさない。実ファイルを作る際の文字サイズ・収まり・表示確認は、その成果物の作成手順で行う。

### 単独で見ても誤解しないか

見出しだけを続けて読む。次に、本文と図表を照合する。タイトルが試算を実績にしていないか、比較条件がそろっているか、図表から導けない解釈を載せていないかを確かめる。資料の抜粋利用が想定される場合は、対象期間や提案中であることが当該ページでも分かるようにする。

## 5. 箇条書き・表・文章を使い分ける

| 伝える関係 | 適する形の候補 | 注意点 |
| --- | --- | --- |
| 同列の要件・対象 | 箇条書き | 同じ階層・観点でそろえる |
| 作業の順序 | 番号付きの手順 | 順番と依存条件を消さない |
| 複数案の比較 | 表 | 同じ項目・単位・条件で比較する |
| 原因と結果、理由 | 短い文章 | 並べるだけで因果を読ませない |
| 依頼や決裁事項 | 明確な一文＋必要な項目 | 項目名だけで依頼内容を隠さない |

「導入費用」「短納期」「担当者が対応」のように、項目名・評価・作業が無関係に混ざっていれば、何を並べたいかから直す。同列の箇条書きの文体と句点の扱いはそろえるが、見出しと本文まで同じ形式にしない。

条件付きの列挙は、導入文の条件がどの項目に掛かるか分かるようにする。対象の一部を挙げた「など」を削ると網羅列挙に変わる場合がある。表の単位を列見出しにまとめるのはよいが、単位そのものを消さない。

## 6. 丁寧さと用語を調整する

社内の報告と対外的な依頼で、距離感を分ける。敬語を重ねるほど丁寧になるわけではないが、直接的にするほど良いわけでもない。依頼の負担や相手が断れる余地に合った表現を選ぶ。

「ご確認いただけますか」は依頼として働く。「確認します」への短縮は、行為者と意味を変えてしまう。「させていただく」は許可を受ける事情や恩恵への配慮があるかを見て判断する。通常の自社の説明では「ご説明します」で足りることが多いが、語形だけで誤りと決めない。

略語やカタカナ語は相手が理解でき、意味が正確なら使う。専門用語を難しい漢語へ置換しても読みやすくはならない。初出の説明が必要な語、定義を変えると困る語、社内で共有済みの語を分ける。顧客、利用者、管理者など異なる役割を、反復回避のため同じ語にしない。

「実施」「推進」「実現」「支援」「活用」は禁止語ではない。対象と行為がすでに明確なら使える。本文が「最適化の実現に向けた取り組みの推進」のような抽象名詞だけなら、資料から行為を取り出す。材料不足なら「何を変える施策か」を確認し、もっともらしい具体策を作らない。

## 7. 文書別に残すもの

- **提案書・稟議書**：提案範囲、費用の範囲、承認してほしい事項。検討段階を契約上の約束に変えない。
- **報告書**：結果、対象・期間、分かったこと、残る論点。事実と所感を分ける。所感に本人が述べていない感情や経験を足さない。
- **議事録**：発言者、決定事項、未決事項、担当・期限。意見が出たことと、決定したことを区別する。
- **依頼メール**：相手にしてほしいこと、理由、資料や対象、既知の期限。挨拶を短くしても、依頼を命令や自社の約束に変えない。
- **役員向け概要**：判断を左右する結論・数値・制約を先に置く。短くする際も、試算の前提や大きな未決事項を隠さない。

## 8. 推敲の判断が割れたら

「短い方」「言い切る方」「柔らかい方」を自動的に選ばない。読み手が元資料と同じ理解に到達でき、必要な判断ができる方を選ぶ。文の長さ、箇条書きの数、語尾の種類に機械的なノルマを置かない。
