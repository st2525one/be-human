# 自然な調子を設計し、文章全体を推敲する

「AIっぽくない文章」、見本文への文体合わせ、新規の記事執筆で参照する。以下は本スキル独自の編集手順であり、論文で効果が実証された日本語の処方箋ではない。研究との対応は [research-notes.md](research-notes.md)。

## 1. 内容の制約と、表現の目標を分ける

依頼・原資料から、次を必要な範囲だけ押さえる。毎回の質問票や、必須の出力様式にはしない。

| 確認するもの | 編集への使い方 |
| --- | --- |
| 目的・読者・媒体 | 読者が知りたい情報と説明の深さを決める |
| 話者・名義 | AIの返答、本人の代筆、組織の説明、引用、創作を区別する |
| 保持する内容 | 数値、条件、否定、対象、進捗、帰属、主張の強さ、必要な論点を固定する |
| 指定された形式 | 文字数、見出し、用語、書式を守る。内容との衝突は隠さない |
| 目指す調子 | 丁寧さ、直接性、専門性、説明量、書き手の視点から、今回効く特徴だけ選ぶ |

例えば「顧客への提案。敬体。作業と役割を先に示す。未検証の効果は断定しない」なら十分。「親しみやすい・厳粛・詩的・短い・網羅的」のように相反する目標を積み重ねない。必須条件を先に守り、好みが競合する場合は読者の理解に寄与する方を選ぶ。

明示がない限り、リライトは意味を保つ編集として扱う。要約や再構成が依頼されていれば、その範囲で情報を選び直す。新規執筆では、材料から導ける判断と根拠を組み立てる。「個性を出す」ために、本人の立場や好みを創作しない。

## 2. 見本文から、使える特徴だけを取り出す

本人の過去文や、ユーザーが選んだ見本文があれば、次の観点から今回の用途に合う特徴を数点読み取る。

- 冒頭で何を先に示すか。結論、状況、出来事など。
- どこまで説明するか。読者に共有されている前提は何か。
- 距離感と語彙。丁寧さ、専門語、口語の使い方。
- 文と段落の進み方。短い判断の後に根拠を置く、具体例から論点へ進む、など。
- 判断の示し方。本人の意見、観察、引用、留保の置き方。

語尾や口癖を数えて全段落に散らさない。見本文から借りるのは表現上の特徴であり、固有の事実、実績、人物関係、体験ではない。文章の題材と文体の手本が同じ資料なら、今回の材料として明示された範囲を見極める。

見本文が少ない場合は、その場の仮の基準にとどめる。「この人は常に断定的」などの恒久的な人物像にしない。見本がなくても着手できる。仕事のメールなら適度な敬体、個人の文章なら原稿の語り口を基準にし、必要以上に洗練させない。

## 3. 単語の前に、段落の役割を直す

各段落が、読者に何を新しく渡すかを見る。新しい情報には、根拠、条件、説明、必要な判断も含む。文脈に役立つ再提示は残す。

| 読みにくさの兆候 | 判断と修正 |
| --- | --- |
| どんな題材にも使える導入 | 今回の事実・依頼・問いから始められるかを見る。必要な背景は残す |
| 「効率化」「価値」「重要」だけで進む | 材料にある対象、作業、変化へ戻す。数値や実績を作って埋めない |
| 見出しと本文と結びが同じ主張 | 本文を根拠・手順・条件に使う。重複する結びを省く |
| どの段落も主張・三点列挙・総括 | 情報の関係で構成を選ぶ。意味のある三点や指定書式は維持する |
| 不要な「AではなくB」や問い掛け | その対比が材料にあり、理解に役立つかを確認する。必要なら保つ |
| 全案を同じ長さで紹介し、判断が見えない | 比較に必要な差を示す。依頼された判断は根拠とともに述べる |
| 語尾や接続詞だけが単調 | まず同じ内容の反復や文の構造を見る。意味を変える言い換えはしない |
| 事実が薄いのに大げさな締め | その文章で分かったことや実際の依頼で終える。無関係な将来像を足さない |

短い結論と長めの根拠が必要な文章もあれば、短文だけで足りる文章もある。長短の交互配置、疑問文の挿入、誤字、脱線、意図的な不統一で自然さを演出しない。声に出すつもりで読み、意味の切れ目と調子の不自然さを確認する。

## 4. 誰の経験・判断なのかを保つ

本人の代筆で、素材に「初めて任されて緊張した」とあれば、その経験と感情を残せる。「私は〜」を機械的に消す必要はない。素材が実施日時だけなら、緊張、喜び、苦労、会場の様子を創作して事実として足さない。

AI自身の返答では、未実施の作業や物理的な経験を、実施・経験したように書かない。「現場で見てきたから分かる」といった説得の演出をしない。実際に資料を確認したことや、比較したうえでの判断は、行った範囲が分かる表現で述べられる。

礼儀、謝意、謝罪、配慮は、場面で働いていれば使う。求められていない過剰な称賛や、本人が述べていない共感を足さない。取引先への謝罪や、本人が書いた気持ちを「擬人化だから」と消さない。創作を依頼された場合は、その設定内で語り手の体験や感情を描ける。

「と思う」「かもしれない」を増減して調子を作る前に、判断者と根拠を確認する。確定した事実を曖昧にせず、未検証の見込みを断定しない。単に根拠のない主張へ「可能性がある」を付けても、根拠が生まれるわけではない。

## 5. 修正後に、別々の観点で読む

**内容の照合を先に行う。** 元の材料と編集稿を双方向に見る。必要な主張・条件が残ったか、追加した記述に根拠があるかを確かめる。誤りがあれば、文体が好ましくても採用しない。これは原資料との忠実性の確認であり、原資料そのものの事実検証とは区別する。

**次に表現の適合を見る。** 読者が要点を追えるか、段落がつながっているか、狙った調子か、不要な反復が減ったか、本人の視点を平板にしていないかを確かめる。問題を指摘するなら箇所と理由を示す。「自然さ95点」のような根拠のない合算値を出さない。

通常は一稿を作って読み返せばよい。調子の判断が割れる部分だけ、意味をそろえた二案を比べる。長い案、丁寧な案、後に作った案を自動的に選ばない。どちらもよければ元の表現を残す。

再編集は具体的な問題のある箇所に絞り、目安として二巡まで。未解決の意味の曖昧さは、何度書き直しても解決しないため、該当点を確認するか未確定として残す。ユーザーの追加指示や訂正は、この目安とは別に反映する。

完成稿のみを求められたら完成稿を出す。診断なら「箇所・理由・修正案」、比較なら指定された案を出す。内部の文体設定や点検表を毎回添付しない。

## 6. 小さな適用例

以下は説明用の架空の材料。実案件の根拠や本人の体験として流用しない。

### 宣伝調を減らす

材料：申請を紙からフォームに変更した。入力項目を12から7に減らした。所要時間は未測定。

元の文：
> デジタル化の推進により、申請業務の飛躍的な効率化と新たな価値創出を実現しました。

編集例：
> 申請を紙からフォームに切り替え、入力項目を12から7に減らしました。所要時間への効果は、まだ測っていません。

効率化を別の形容詞で言い換えず、実施した変更を示す。「飛躍的」を削っても、未測定の効果を断定したままなら修正不足。

### 書き手の調子を残す

本人の材料：初めて顧客説明を担当した。途中で言葉に詰まった。最後まで説明した。

原稿：
> 初めて説明を任された。途中で言葉に詰まったけど、最後まで話せた。

個人の日記なら、十分伝わるためそのまま残せる。「貴重な経験を通じて大きく成長しました」という評価や、聞き手の反応を足さない。業務報告への変更を頼まれた場合は、その用途に合わせる。

### 同じ材料を、相手に合わせる

材料：仕様書の第3節を修正した。公開前に確認が必要。確認依頼の期限は10月22日。

同僚への短い連絡：
> 仕様書の第3節を直しました。公開前に確認をお願いしたいので、10月22日までに見てもらえますか。

顧客への依頼：
> 仕様書の第3節を修正しました。公開前の確認が必要なため、10月22日までにご確認いただけますか。

同じ内容と期限を保ち、距離感を変える。ユーザーが書いた短文に合わせて、全ての成果物をくだけた調子にしない。
